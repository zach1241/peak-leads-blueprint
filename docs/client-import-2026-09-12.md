## Application behavior

`/delivery` shows monthly and weekly numerical commitments, quantity/range, client/service, period and status. Client filtering and separate managed responsibility controls reuse the existing shell. Task details allow actual quantity updates, and client/project/dashboard links make delivery discoverable.

Opening Delivery automatically calls an authenticated Server Action to generate only the current monthly and actionable weekly periods. The unique constraint and `ON CONFLICT DO NOTHING` make repeated opens/retries safe. No GET/Server Component performs writes. There is no unattended scheduler: periods are generated on use, not while everyone is offline. Past tasks remain in Tasks; missed historical periods are not backfilled. A scheduled worker and configurable recurrence calendar can be added later if needed.
